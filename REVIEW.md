# Правила ревью

Этот документ описывает чеклист и критерии ревью для всех PR в репозитории expense-tracker.

---

## Общие правила

- [ ] Ветка названа по схеме `<type>/<short-description>` (типы: `feat`, `fix`, `refactor`, `chore`, `docs`, `ci`).
- [ ] Коммиты следуют [Conventional Commits](https://www.conventionalcommits.org/): `<type>(<scope>): <description>`.
- [ ] Subject line коммита — повелительное наклонение, строчные буквы, без точки, ≤ 72 символа.
- [ ] PR title — по Conventional Commits, ≤ 72 символа.
- [ ] PR описывает *что* сделано и *зачем* (секция «Что сделано»).
- [ ] Для новых/изменённых endpoints заполнена секция «Изменения API».
- [ ] Есть чеклист ручного тестирования («План проверки»).
- [ ] Нет смешивания рефакторинга с функциональными изменениями в одном PR.

---

## TypeScript

- [ ] Нет `any` без явного обоснования в комментарии.
- [ ] Все публичные функции и методы типизированы (аргументы и возвращаемое значение).
- [ ] Новые типы, шаренные между фронтом и бэком, добавлены в `@repo/shared-types`, а не дублируются.
- [ ] Нет `@ts-ignore` / `@ts-expect-error` без объяснения.

---

## Бэкенд (`apps/api`)

### Архитектура CQRS + Repository

- [ ] Мутации реализованы через **Command Handler**, чтение — через **Query Handler**.
- [ ] Контроллер инжектирует только `CommandBus` и `QueryBus`, не сервисы напрямую.
- [ ] Все запросы к Prisma инкапсулированы в **Repository**-классе (`*Repository`), не размазаны по handlers.
- [ ] Новый ресурс: есть контроллер, команды/запросы, handlers, repository — по аналогии с `transactions/` или `categories/`.

### Безопасность и авторизация

- [ ] Все защищённые роуты имеют `@UseGuards(JwtAuthGuard)` на уровне контроллера.
- [ ] Запросы к БД фильтруются по `userId` из JWT-payload — данные одного пользователя недоступны другому.
- [ ] Нет утечки внутренних деталей в ответах ошибок (стектрейсы, SQL).

### DTO и валидация

- [ ] Все поля DTO декорированы валидаторами из `class-validator`.
- [ ] Update-DTO использует `PartialType` из `@nestjs/mapped-types`.
- [ ] Для дублирующего email или имени категории выбрасывается `ConflictException`.
- [ ] Для отсутствующего ресурса выбрасывается `NotFoundException`.
- [ ] Нет ручного парсинга тела запроса — всё через `ValidationPipe` (`whitelist: true`, `transform: true`, `forbidNonWhitelisted: true`).

### База данных / Prisma

- [ ] После изменения схемы (`schema.prisma`) создана и применена миграция (`pnpm db:migrate`).
- [ ] После изменения схемы запущен `pnpm db:generate` (пересборка Prisma Client).
- [ ] Уникальные ограничения в схеме соблюдены: `(userId, name)` для Category, индекс `(userId, date)` для Transaction.
- [ ] Поле `amount` хранится как `Decimal(12,2)` — нет попыток хранить его как `Float` или `Int`.
- [ ] Каскадные удаления в схеме не нарушены.

### Конфигурация

- [ ] Новые переменные окружения добавлены в `.env.example` и задокументированы в `apps/api/CLAUDE.md`.
- [ ] Новые переменные читаются через `ConfigService`, не через `process.env` напрямую.

---

## Фронтенд (`apps/web`)

### Архитектура FSD

- [ ] Новые файлы размещены в правильном слое: `shared` → `entities` → `features` → `views` → `widgets` → `app`.
- [ ] Импорты идут только «вниз по слоям»: верхний слой импортирует нижний, но не наоборот.
- [ ] Zod-схемы форм лежат в `<feature>/model/schema.ts`.
- [ ] API-запросы и React Query хуки лежат в слое `entities` или `features`, не в компонентах напрямую.

### Данные и состояние

- [ ] После успешной мутации вызывается `queryClient.invalidateQueries()` для инвалидации кэша.
- [ ] Поле `amount` конвертируется из строки в `number` через Zod-схему, не вручную в компоненте.
- [ ] Новые shadcn/ui компоненты добавлены через `npx shadcn add <component>`, не написаны вручную.

### HTTP-клиент и аутентификация

- [ ] Все запросы к API идут через `apiFetch()` из `src/shared/api/http-client.ts`.
- [ ] Токен хранится и читается только через функции из `src/shared/lib/token.ts` (`setToken`, `getToken`, `clearToken`).
- [ ] Нет прямого обращения к `document.cookie` или `localStorage` для токена.
- [ ] Публичные маршруты добавлены в `PUBLIC_PATHS` в `src/middleware.ts`, если нужна публичная доступность.

### UI и формы

- [ ] Формы используют `react-hook-form` + `zod`-резолвер, не неуправляемые input'ы.
- [ ] Состояния загрузки и ошибок обработаны и отображены пользователю.
- [ ] Нет инлайновых стилей — только Tailwind-классы (с `cn()` для условных классов).

### Переменные окружения

- [ ] Новые переменные окружения добавлены в `.env.example`.
- [ ] Переменные, нужные на клиенте, имеют префикс `NEXT_PUBLIC_`.

---

## Безопасность (общее)

- [ ] Нет секретов, токенов или паролей в коде или комментариях.
- [ ] Нет SQL-инъекций — все запросы через Prisma (параметризованные).
- [ ] Нет XSS — нет `dangerouslySetInnerHTML` с пользовательским вводом без санитизации.
- [ ] Нет незащищённых endpoint'ов, которые должны быть закрыты.

---

## Тесты

- [ ] Новая бизнес-логика покрыта юнит-тестами.
- [ ] Тесты не мокируют БД там, где важна интеграция с реальной схемой.
- [ ] Тесты запускаются командой `pnpm test` без ошибок.

---

## Чек-лист для ревьюера

- [ ] PR title соответствует Conventional Commits
- [ ] Код собирается и линтер проходит
- [ ] FSD-слои не нарушены (фронтенд)
- [ ] CQRS и Repository pattern соблюдены (бэкенд)
- [ ] Эндпоинты защищены JwtAuthGuard где нужно
- [ ] Нет утечек данных между пользователями (проверка userId)
- [ ] DTO покрывают все входные данные
- [ ] Нет any, console.log, закомментированного кода
- [ ] Prisma-миграция создана при изменении схемы

### Пропускать при ревью

Следующие файлы генерируются автоматически — не рецензировать содержимое:

- Сгенерированные файлы миграций в `prisma/migrations/*`
- Изменения в `*.lock`-файлах
