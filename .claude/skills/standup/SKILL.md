# standup

Подготовить детальный отчёт о работе за вчерашний день на основе git-коммитов — для выступления на стендапе.

## Порядок работы

1. Определить вчерашнюю дату:

```bash
date -d "yesterday" "+%Y-%m-%d"
```

2. Получить все коммиты за вчера с автором:

```bash
git log --all --no-merges \
  --after="YYYY-MM-DD 00:00:00" \
  --before="YYYY-MM-DD 23:59:59" \
  --format="%H %an %s"
```

3. Для каждого коммита получить подробный diff:

```bash
git show --stat --patch <hash>
```

4. Также проверить все ветки, где были коммиты вчера:

```bash
git log --all --oneline --no-merges \
  --after="YYYY-MM-DD 00:00:00" \
  --before="YYYY-MM-DD 23:59:59" \
  --format="%D %s"
```

## Формат вывода

Сформируй отчёт на русском языке в следующем виде:

---

**Стендап — [дата]**

**Что сделано:**

[Для каждого значимого изменения — пункт списка с объяснением что было реализовано и зачем, на основе кода из diff. Группируй по смыслу (фронтенд / бэкенд / база данных / конфигурация). Не просто повторяй subject коммита — раскрой суть изменений.]

**Коммиты:**

| Автор | Коммит |
| ----- | ------ |

[Краткая таблица: имя автора и subject коммита (`тип(scope): описание`) для каждого коммита за вчера.]

**Ветки:**

[Перечисли ветки, в которых велась работа]

**Планы на сегодня:**

[Оставь пустым — пользователь заполнит сам]

---

## Правила

- Анализируй фактический код из diff, а не только заголовки коммитов.
- Если коммитов за вчера нет — сообщи об этом явно.
- Пиши по-русски, в деловом стиле, кратко и по делу.
- В таблице коммитов указывай имя автора и subject коммита — без хэшей.
- Группируй изменения по области (api / web / database / конфигурация), если их несколько.
